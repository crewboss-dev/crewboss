Open PowerShell (not as admin) and install Git and Python. Close PowerShell and open a new one afterwards, so it finds them: {% call pre() %}winget install --id Git.Git -e winget install --id Python.Python.3.12 -e{% endcall %}

Install Claude Code for Windows and sign in (it needs Git for Windows, installed above): {% call pre() %}irm https://claude.ai/install.ps1 | iex claude # sign in once, then /exit{% endcall %}
Get the code and install the runner. The first clone opens your browser to sign in to GitHub (Git Credential Manager, part of Git for Windows); after that it remembers. This clone is only for installing the runner; Android projects go on a Dev Drive (below): {% call pre() %}git clone {{ repo }} crewboss cd crewboss py -m pipx install .\runner crewboss-runner --version{% endcall %}

Android on this PC, natively PowerShell runs Windows EXE/MSI jobs, and Android jobs when the Android work lives on this PC.

  • Android Studio (it brings its own Java, in its jbr folder, so no separate JDK is needed). Skip the install if you already have it: {% call pre() %}winget install --id Google.AndroidStudio -e{% endcall %} Point command-line builds (the runner's) at that Java: {% call pre() %}$jbr = "C:\Program Files\Android\Android Studio\jbr" [Environment]::SetEnvironmentVariable("JAVA_HOME", $jbr, "User") $p = [Environment]::GetEnvironmentVariable("Path", "User") [Environment]::SetEnvironmentVariable("Path", "$p;$jbr\bin", "User"){% endcall %} Open Android Studio once, then Settings > Languages & Frameworks > Android SDK > SDK Tools: tick "Android SDK Command-line Tools", "Platform-Tools" and "Android Emulator". Accept the licences with sdkmanager --licenses (in %LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest\bin).
  • Keep the repo and the Gradle caches on a Dev Drive: Windows 11 Settings > System > Storage > Disks & volumes > Create dev drive (Defender's performance mode is on by default for Dev Drives). Clone the repo there, for example D:\work.
  • Put adb and the emulator on the PATH, natively (PowerShell, one time): {% call pre() %}$sdk = "$env:LOCALAPPDATA\Android\Sdk" [Environment]::SetEnvironmentVariable("ANDROID_HOME", $sdk, "User") $p = [Environment]::GetEnvironmentVariable("Path", "User") [Environment]::SetEnvironmentVariable("Path", "$p;$sdk\platform-tools;$sdk\emulator", "User"){% endcall %} (This adds to your own PATH only. Don't use setx PATH: it cuts long paths at 1024 characters.) Open a new PowerShell afterwards. The emulator uses the NVIDIA GPU here; a phone on USB works with plain adb devices.
  • Give the runner the label android (and android-usb if a phone is plugged in), plus windows for EXE/MSI. To pin a project to this native runner rather than a WSL2 one, also add android-ps and use a job profile that requires it.

An honest note: Gradle builds run on the CPU, RAM and disk. The NVIDIA GPU speeds up the emulator, not the build.

  1. Make a code, then enrol Make a code above (Mode: Subscription); it works once, for 5 minutes. Copy the whole code, including the part after #. On the PC, within 5 minutes: {% call pre() %}crewboss-runner enrol '<code>'{% endcall %} Add --runner-name <pc-name> if you want; the default is the hostname. If this dashboard is a localhost install (an address that starts http://localhost, no https), add --insecure-http to enrol; without it the runner tries https and fails with an SSL error. It checks this dashboard's key against the fingerprint in the code before it sends anything, then keeps its own key and token in the PC's secret store (the OS keyring: Windows Credential Manager, macOS Keychain, or the desktop keyring on Linux).
    Already have a runner for another Crewboss? Add this one as a profile (this works the same on Linux, Windows PowerShell, WSL and macOS; one PC can hold several, one active at a time): {% call pre() %}crewboss-runner enrol '<code>' --name {{ profile_hint or 'work' }} crewboss-runner use {{ profile_hint or 'work' }}{% endcall %} crewboss-runner profiles lists them (the active one is marked), crewboss-runner use <name> switches and reconnects (it refuses while a job runs unless you add --force), and crewboss-runner profile remove <name> deletes one (revoke it on that Crewboss's Runners page too). A profile name is 1-32 of a-z 0-9 -. Every server enrolled on one PC can read the others' keys and repositories (the same OS user): servers that must not trust each other need separate OS users or PCs, so do not put two unrelated clients on one PC this way.

Something wrong? Run the doctor On the PC, crewboss-runner doctor checks Python, git, Claude Code and its sign-in, the keyring, this dashboard's pinned key, the enrolment, the label tools (add --label android-usb), the autostart, disk space and the agent's setup (hooks, MCP servers, permissions, stray secrets), and says pass, warn or fail for each. crewboss-runner doctor --json prints it for a script. crewboss-runner repair fixes the safe things (asking first; --yes skips the questions). crewboss-runner uninstall removes the autostart, this PC's key and settings, and leaves your repositories alone, and refuses to delete a folder that is not the runner's own (named crewboss-runner or holding its marker file) or while a job is running. Where it keeps things can be moved with CREWBOSS_RUNNER_CONFIG_DIR and CREWBOSS_RUNNER_STATE_DIR (absolute paths). The scan looks for known risky patterns; "no known-risky setup found" is not a guarantee.

4. Keep it running It saves this terminal's PATH into the autostart (so it can find claude, the Android tools and the rest); run it again after installing new tools. One command makes a systemd user service that starts when you log in (it writes the unit file for you): {% call pre() %}crewboss-runner service install crewboss-runner service status journalctl --user -u crewboss-runner -f{% endcall %} The log includes the status page link (it opens only on that PC). crewboss-runner service uninstall reverses it; add --dry-run to see what it would do first. It runs while you are logged in, which is what Subscription mode needs: it uses your Claude login, and the runner's key is in your keyring. To try it in the terminal first, crewboss-runner run (Ctrl+C stops it).

No tray here The tray icon is Windows-only (crewboss-runner tray says so). Use the commands above: status, doctor, service start|stop. The same local control panel page also works: crewboss-runner status prints its link while the runner is running (optional).

Sleep While a job is running the runner keeps this PC from going to sleep on its own (systemd-inhibit), and lets go as soon as no job is running; an idle runner never keeps it awake, and the screen may still turn off. This stops idle sleep only: closing a laptop lid or pressing the power button still sleeps the PC, so plug in and leave the lid open for long jobs. Turn it off with CREWBOSS_RUNNER_KEEP_AWAKE_DURING_JOBS=0.

4. Keep it running One command makes a hidden per-user Scheduled Task that starts the runner when you log in to Windows (no admin needed, no console window), and starts it now: {% call pre() %}crewboss-runner service install crewboss-runner status{% endcall %} status prints the status page link (it opens only on that PC) and shows whether the runner is running; the runner's log is %LOCALAPPDATA%\crewboss-runner\logs\<profile>\runner.log (profile default unless you added more). Stop or start it with crewboss-runner service stop (a graceful stop; it refuses while a job runs unless you add --force) and crewboss-runner service start; crewboss-runner service uninstall removes it. To try it in the terminal first, crewboss-runner run (Ctrl+C stops it).

Optional: tray icon and control panel crewboss-runner tray (or crewboss-runner-tray, no console window) puts an icon in the notification area: grey = stopped, green = idle and connected, blue = a job is running, amber = needs attention. Its menu starts and stops the runner and opens the control panel (state, current job, automatic start, keep-awake, health, log, and "Remove runner from this PC"). A checkbox in the panel starts the tray when you sign in. No admin needed; only choosing the Windows service asks for it.

Optional: a real Windows service From an administrator PowerShell opened by the same user, crewboss-runner service install --windows-service installs a service that logs on as you (it asks for your Windows password, which goes straight to Windows and is not stored), starts at boot (delayed) and restarts on failure. It runs as you, with standard-user rights, even though it is a service: the service only supervises and starts the runner with a filtered (non-administrator) token, so the agents do not get admin rights. It runs as you, not as SYSTEM, because the key store and your Claude Code login belong to your user. A service has no desktop and cannot open a browser, so sign in to Claude Code (run claude once) before installing. The service runs from its own admin-only copy in Program Files (so Python must be installed for all users, not just for you; after pipx upgrade, re-run the install to update it). Entra ID (AzureAD) accounts cannot be service accounts: use the hidden task. Installing one kind removes the other; stopping, starting and removing the service need an administrator PowerShell.

Sleep While a job is running the runner keeps this PC from going to sleep on its own (Windows power request), and lets go as soon as no job is running; an idle runner never keeps it awake, and the screen may still turn off. This stops idle sleep only: closing a laptop lid or pressing the power button still sleeps the PC, so plug in and leave the lid open for long jobs. Turn it off with CREWBOSS_RUNNER_KEEP_AWAKE_DURING_JOBS=0.

  1. crewboss-runner status shows the connection and any job.
  2. Back here, give the runner its labels (for example android, android-usb for a PC with a phone on USB, windows, macos). A job whose profile needs a label only goes to runners that have it.
  3. How a job runs: the runner starts a Claude Code session named dash-j<job> in its own git worktree. Drive it from claude.ai/code or the phone and answer its permission prompts there. When it ends, the runner pushes the branch. Merge and deploy go through the dashboard.
  4. Removing a PC: run crewboss-runner forget on the PC, then press Revoke here. If a code expired, make a new one.

If a job never shows up at claude.ai/code, run claude on the PC (inside WSL for the WSL2 runner) and sign in. The runner shows "not signed in" and takes no jobs until you do, and you get a notification if a session cannot start.
