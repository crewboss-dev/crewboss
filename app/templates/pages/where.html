Gemini for jobs

Lets a job on a runner that holds a Gemini API key ask Google's Gemini for a second opinion on a plan or design, and make logos and other pictures. When this is on, text the job chooses to send leaves for Google (secrets are scrubbed first, best effort; Gemini is called with no tools and cannot see the repository). Off by default. Every call is counted below; nothing it makes is published. This switch governs the Gemini tools only; it is not a sandbox. A job with Bash on a runner where the key file is reachable could read it: the runner has no separate operating-system user for jobs.

Server reads

What a job may look at on each server, to diagnose a problem there: a container's logs, a unit's journal, one log file or one fixed probe command. A job asks by name; Crewboss runs that one read with a one-minute pass that can run nothing else, and the server's own /etc/crewboss/reads.conf is the final list. Output comes back capped and with secrets scrubbed, labelled as untrusted. A probe may run only a program from a fixed read-only list (systemctl status, docker ps, ss, df and similar), never a command that changes anything. Reads run as root on the server. Installing the generated file below is the server admin's approval of each read listed in it, so review it before you save it there.
